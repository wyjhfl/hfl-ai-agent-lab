# RAG 工程化

## 这一节解决什么问题

RAG 的 Demo 通常只有几行代码，但要做到生产可用，需要处理文档解析、分块、向量化、检索、重排序、上下文管理等一系列工程问题。

## Pipeline 全景

```text
原始文档 → 解析 → 切分 → 向量化 → 存储 → 检索 → 重排序 → 上下文组装 → LLM 生成
```

## 各环节要点

### 文档解析

需要处理多种格式：PDF、Word、Markdown、HTML。

常见问题：

- 表格提取
- 图片处理
- 编码问题
- 元数据保留

### 文本切分

切分策略直接影响检索质量。

常用方法：

- 按段落切分
- 按句子切分
- 滑动窗口
- 语义切分

关键原则：

- 块大小要适中（太大噪音多，太小上下文丢）
- 保留元数据（来源、页码）
- 处理好块之间的边界

### 向量化

选择合适的 Embedding 模型，考虑：

- 维度
- 速度
- 多语言支持
- 领域适配

### 检索

基础是向量相似度搜索，但可以优化：

- 混合检索（向量 + 关键词）
- 过滤条件
- 分数阈值

### 重排序

初步检索结果可能不够精准，用 Reranker 二次排序：

- Cross-encoder 重排序
- 分数融合

### 上下文组装

把检索到的块组装成 LLM 能理解的上下文：

- 控制总长度
- 保留来源引用
- 处理重复内容

## 面试表达

可以这样表达：

> RAG 不只是"把文档切一切然后检索"。我关注的是整个 Pipeline 的工程化：文档解析要处理多种格式，切分要平衡块大小和语义完整性，检索要支持混合搜索和过滤，重排序要提升精准度，最后上下文组装要控制长度并保留来源。每个环节都会影响最终的回答质量。
