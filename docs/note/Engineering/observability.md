# 日志与可观测性

## 这一节解决什么问题

Agent 系统的执行链路长、涉及模块多，没有可观测性就无法定位问题和优化性能。

## 三大支柱

### 1. Logs（日志）

记录系统中发生的事件。

AI 应用需要记录：

- 用户请求
- 模型调用（输入、输出、耗时）
- 工具调用（参数、结果、耗时）
- 错误信息
- 业务事件

结构化日志示例：

```json
{
  "timestamp": "2026-05-20T10:00:00Z",
  "level": "info",
  "event": "tool_call",
  "tool": "query_database",
  "duration_ms": 150,
  "success": true
}
```

### 2. Traces（链路追踪）

记录一次请求的完整执行路径。

Agent 系统的 Trace 需要包含：

- 请求入口
- Agent 调用
- 模型调用
- 工具调用
- 状态变化
- 最终输出

每个节点记录：

- 开始时间
- 结束时间
- 输入
- 输出
- 父节点 ID

### 3. Metrics（指标）

用于监控系统健康状态。

关键指标：

- 请求量
- 响应时间
- 模型调用耗时
- 工具调用成功率
- 错误率
- Token 消耗量

## 实践建议

1. 从第一天就加日志，不要等到出问题再补
2. 用统一的日志格式，方便后续分析
3. Trace 要覆盖完整链路，不能只记部分
4. Metrics 要关注趋势，不只是当前值
5. 错误日志要包含足够上下文，方便定位

## 面试表达

可以这样表达：

> Agent 系统的可观测性是我重点关注的方向。我会为每次执行生成完整的 Trace，记录从用户输入到最终输出的每个步骤；用结构化日志记录关键事件；用 Metrics 监控系统健康状态。这样出了问题能快速定位，也能为后续优化提供数据支撑。
