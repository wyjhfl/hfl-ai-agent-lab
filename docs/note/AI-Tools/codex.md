# Codex 拆解

## 当前定位

Codex 更适合 IDE 内代码生成、局部实现、函数级修改、版本实现和教学式开发流程。

相比 Claude Code 的仓库级操作，Codex 更侧重于代码层面的辅助：写函数、补测试、改接口、解释代码。

## 核心能力

### 根据项目上下文生成代码

Codex 可以读取项目中的已有代码，根据上下文生成新代码。这让生成的代码更符合项目风格和约定。

### 修改局部模块

Codex 适合修改单个文件或单个函数，而不是跨多个文件的重构。这让它在局部开发中效率很高。

### 辅助调试

Codex 可以解释错误信息、分析代码行为、建议修复方案。这让调试过程更高效。

### 解释代码

Codex 可以解释已有代码的逻辑，帮助理解陌生代码库。这在接手新项目时特别有用。

### 按版本目标推进实现

Codex 可以配合 AGENTS.md 等项目规则，按版本目标逐步推进实现。

## 适合做什么

- 实现具体函数
- 补全测试
- 修改接口
- 解释已有代码
- 按 AGENTS.md 执行项目规则
- 生成代码片段
- 重构单个模块

## 不适合做什么

- 没有规划时直接乱写
- 一次性重构全部项目
- 在需求不清楚时生成复杂架构
- 绕过人工审查直接合并
- 需要理解整个仓库上下文的场景
- 需要跨多个文件协调修改的场景

## 教学式使用方式

Codex 特别适合"先讲原理，再做实现"的教学式开发流程：

1. 先让 Codex 解释某个概念或模式
2. 再让它根据解释生成实现
3. 审查生成的代码是否符合预期
4. 根据反馈调整

这种方式适合配合项目 A / 项目 B 的版本迭代：先理解要做什么，再逐步实现。

## 和 Claude Code 的分工

| 场景 | 推荐工具 |
|------|----------|
| 批量文件修改 | Claude Code |
| 单个函数实现 | Codex |
| 文档站结构调整 | Claude Code |
| 代码解释 | Codex |
| 构建检查 | Claude Code |
| 测试补全 | Codex |
| 版本迭代执行 | Claude Code |
| 局部重构 | Codex |

## 使用经验

### 先规划再实现

不要直接让 Codex 写代码，先明确要实现什么、输入输出是什么、边界在哪里。

### 审查生成代码

Codex 生成的代码需要人工审查，确保逻辑正确、风格一致、没有安全问题。

### 配合 AGENTS.md

在项目中维护 AGENTS.md，记录项目约定、代码风格、架构决策。Codex 可以根据这些规则生成更符合项目要求的代码。
