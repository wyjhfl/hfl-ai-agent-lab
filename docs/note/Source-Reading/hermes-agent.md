# Hermes Agent 源码拆解

## 项目定位

Hermes Agent 用于学习一个 Agent 系统从用户输入到任务执行的基本链路。

拆解它的重点不在于逐行阅读源码，而在于理解：

- Agent 如何接收任务
- 如何维护上下文
- 如何选择工具
- 如何执行动作
- 如何返回结果

## 核心观察点

### 1. Agent 入口

首先要找到 Agent 的启动入口，理解系统是如何接收用户输入的。

重点关注：

- 输入参数是什么
- 是否有统一的任务对象
- 是否有运行上下文
- 是否有状态初始化过程

### 2. 任务规划

Agent 通常不会直接执行用户请求，而是先把请求转化为可执行步骤。

重点关注：

- 是否有 Planner
- 是否区分计划和执行
- 是否支持多步骤任务
- 是否支持中间状态记录

### 3. 工具调用

工具调用是 Agent 从"聊天"走向"执行"的关键。

重点关注：

- 工具如何注册
- 工具如何被选择
- 工具参数如何生成
- 工具结果如何返回给 Agent

### 4. 状态管理

一个工程化 Agent 需要保存执行过程，而不是每一步都无状态运行。

重点关注：

- 是否维护 memory
- 是否维护 task state
- 是否记录 observation
- 是否记录 tool result

### 5. 错误处理

真实系统中工具调用可能失败，模型输出也可能不稳定。

重点关注：

- 是否有 retry
- 是否有 fallback
- 是否有异常捕获
- 是否有错误信息回传

## 可迁移设计

Hermes Agent 可以重点迁移这些思想：

- 把用户输入封装成任务对象
- 把 Agent 执行拆成计划、行动、观察、总结几个阶段
- 工具调用结果要结构化保存
- Agent 不应该只返回最终答案，还应该保留中间执行轨迹

## 面试表达

可以这样表达：

> 我在阅读 Hermes Agent 时，重点关注的不是某个函数怎么写，而是它如何把用户请求转化为一个可执行任务链路。一个可用的 Agent 系统至少要包含任务输入、计划生成、工具调用、状态维护和结果总结几个核心部分。
