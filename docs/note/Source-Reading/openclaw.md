# OpenClaw 架构拆解

## 项目定位

OpenClaw 适合用来学习复杂 Agent 系统的模块分层、任务编排和系统边界设计。

拆解 OpenClaw 时，重点不是一开始陷入所有源码细节，而是先理解整体结构：

- 系统分几层
- Agent 如何协作
- 工具如何接入
- 状态如何流转
- 任务如何结束

## 核心观察点

### 1. 系统分层

复杂 Agent 项目通常会拆成多个层次：

- 接入层
- Agent 层
- 工具层
- 状态层
- 评测层
- 展示层

这样做的好处是降低耦合，让每个模块只负责自己的职责。

### 2. Agent 编排

多 Agent 系统的重点不是"多个 Agent 聊天"，而是有规则地协作。

重点关注：

- 谁负责接收任务
- 谁负责任务分解
- 谁负责具体执行
- 谁负责检查结果
- 谁负责总结输出

### 3. 工具抽象

工具层决定 Agent 是否能真正执行任务。

重点关注：

- 工具是否统一封装
- 工具参数是否结构化
- 工具结果是否标准化
- 是否支持错误处理

### 4. 状态流转

多 Agent 系统必须维护共享状态，否则不同 Agent 之间无法稳定协作。

重点关注：

- 状态对象包含什么字段
- Agent 如何读写状态
- 状态是否能恢复
- 状态是否能用于调试

## 可迁移设计

OpenClaw 中值得迁移的设计包括：

- 将 Agent 系统拆成清晰分层
- 让每个 Agent 只负责一个明确职责
- 使用状态对象串联多步骤任务
- 将工具调用结果标准化
- 为后续评测和回放保留执行过程

## 面试表达

可以这样表达：

> 我在拆解 OpenClaw 时，重点关注它如何把复杂 Agent 系统拆成多个层次。我的理解是，多 Agent 项目不能只是多个角色的 Prompt 拼接，而应该有明确的调度逻辑、状态流转、工具接口和结果评估机制。
