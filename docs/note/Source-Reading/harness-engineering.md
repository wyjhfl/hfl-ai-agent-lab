# Harness Engineering 源码拆解

## 项目定位

Harness Engineering 更适合用来学习 Agent 工程化、执行链路、评测反馈和质量控制。

相比普通 Agent Demo，它更值得关注的是：

- 如何组织执行流程
- 如何记录过程
- 如何评估结果
- 如何形成反馈闭环

## 核心观察点

### 1. 执行链路

工程化 Agent 项目通常不是一次模型调用，而是一条完整执行链路。

重点关注：

- 任务从哪里进入
- 中间经过哪些模块
- 每个模块的输入输出是什么
- 执行失败后如何处理

### 2. Trace 记录

Agent 项目需要记录执行过程，否则很难调试和优化。

重点关注：

- 是否记录每一步输入输出
- 是否记录工具调用参数
- 是否记录模型响应
- 是否记录失败原因

### 3. Evaluator 机制

评测机制可以帮助判断 Agent 的结果是否可靠。

重点关注：

- 如何判断任务是否完成
- 如何判断结果是否符合预期
- 是否有自动评分
- 是否有人类反馈入口

### 4. Feedback Loop

优秀的 Agent 系统不应该只执行一次，而应该能从失败中获得改进信息。

重点关注：

- 失败是否会被记录
- 是否能生成改进建议
- 是否支持重新执行
- 是否能积累评测样本

## 可迁移设计

Harness Engineering 中值得迁移的设计包括：

- 为每次执行生成 trace
- 将执行结果和评估结果分开
- 引入 Evaluator 检查结果质量
- 将失败样本沉淀为后续优化依据

## 面试表达

可以这样表达：

> 我在学习 Harness Engineering 时，重点关注 Agent 工程化中的 Trace 和 Evaluation。因为 Agent 项目如果没有执行记录和质量评估，就很难从 Demo 走向可维护系统。我的理解是，Agent 不仅要能完成任务，还要能解释它怎么完成、哪里失败、后续如何改进。
