# Multi-Agent 架构

## 这一节解决什么问题

单 Agent 在复杂场景下会遇到上下文过长、职责不清、难以调试的问题。Multi-Agent 通过职责分离解决这些问题。

## 核心模式

### Supervisor 模式

由一个 Supervisor Agent 负责任务理解和调度，其他 Agent 各司其职。

```text
用户请求 → Supervisor → (数据分析) → Data Analyst
                      → (工具调用) → Tool Executor
                      → (风险审查) → Risk Reviewer
                      → 结果整合 → 输出
```

优点：职责清晰，易于扩展
缺点：Supervisor 成为瓶颈

### 对等协作

Agent 之间没有层级关系，通过消息传递协作。

优点：灵活
缺点：难以控制流程

### 层级调度

多层 Supervisor，逐级分解任务。

优点：适合超大任务
缺点：延迟增加

## 关键设计问题

### 1. 角色拆分

每个 Agent 应该有明确的职责边界，不能所有 Agent 做同样的事。

### 2. 状态共享

Agent 之间需要共享上下文，但不能互相覆盖。

### 3. 调度策略

需要决定谁先执行、谁后执行、失败了怎么办。

### 4. 结果整合

多个 Agent 的输出需要合并成一个连贯的结果。

## 面试表达

可以这样表达：

> 多 Agent 不是把多个 Prompt 拼在一起。我的理解是，多 Agent 需要明确的职责拆分、状态共享机制、调度策略和结果整合方式。我采用 Supervisor 模式，让每个 Agent 只负责自己的领域，通过状态机控制流转顺序。
