# Trace 与 Evaluation

## 这一节解决什么问题

Agent 项目如果没有执行记录和质量评估，就很难从 Demo 走向可维护系统。

## Trace

### 什么是 Trace

Trace 是 Agent 执行过程的完整记录，包括：

- 用户输入
- 模型推理
- 工具调用参数
- 工具返回结果
- 中间状态变化
- 最终输出

### 为什么需要 Trace

- 调试：出了问题能定位原因
- 优化：分析哪些步骤可以改进
- 审计：满足合规要求
- 评测：为自动评估提供数据

### Trace 记录什么

每次执行至少记录：

- 时间戳
- 节点名称
- 输入内容
- 输出内容
- 耗时
- 是否成功
- 错误信息

## Evaluation

### 自动评测

通过预定义的指标自动判断结果质量：

- 任务完成率
- 工具调用准确率
- 结果相关性
- 幻觉率

### 人工评审

人工抽样检查执行结果，发现自动评测遗漏的问题。

### 失败分析

记录失败样本，分析失败原因：

- 模型理解错误
- 工具选择错误
- 参数生成错误
- 工具执行失败
- 流程设计缺陷

## 面试表达

可以这样表达：

> Agent 项目不能只看能不能跑通，还要看执行过程是否可追踪、结果是否可评估。我会为每次执行生成 Trace，记录完整的输入输出和中间状态，然后通过自动评测和人工抽样来判断质量，最后把失败样本沉淀为优化依据。
