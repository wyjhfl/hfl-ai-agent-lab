# LangGraph 状态机

## 这一节解决什么问题

LangGraph 用状态机的方式编排 Agent 流程，让多步骤任务不再完全依赖模型自由生成，而是有明确的流转规则。

## 核心概念

### State

状态是整个图的数据载体，所有节点共享同一个状态对象。

状态通常包含：

- 用户输入
- 任务计划
- 工具调用结果
- 中间推理
- 最终输出

### Node

节点是执行单元，每个节点完成一个具体任务后将结果写入状态。

节点可以是：

- 一个 Agent
- 一个工具调用
- 一个数据处理步骤
- 一个人工审核点

### Edge

边定义了节点之间的流转关系。

- 普通边：A 完成后直接到 B
- 条件边：根据状态中的某个字段决定下一步去哪

### Checkpoint

检查点用于保存中间状态，支持：

- 断点恢复
- 流程回溯
- 调试查看

### Human-in-the-loop

LangGraph 支持在特定节点暂停执行，等待人工输入后继续。

## 设计模式

### 线性流程

```text
输入 → Agent A → Agent B → 输出
```

### 条件分支

```text
输入 → Agent A → 判断 → (成功) → Agent B
                    → (失败) → Agent C
```

### 循环

```text
输入 → Agent A → 判断 → (未完成) → Agent A
                    → (完成) → 输出
```

## 面试表达

可以这样表达：

> 我用 LangGraph 把 Agent 的执行过程显式建模为状态机。每个节点是一个处理单元，边定义流转条件，状态在节点间传递。这样做的好处是流程可控、可调试、可暂停，比让模型自由生成多步推理要稳定得多。
