# Tool Calling

## 这一节解决什么问题

Tool Calling 是 Agent 从"能聊天"变成"能做事"的关键能力。

没有 Tool Calling，模型只能生成文本；有了 Tool Calling，模型可以驱动外部系统完成真实操作。

## 核心机制

### Function Calling 协议

大模型通过结构化 JSON 描述可用工具，模型根据用户请求选择工具并生成参数。

```text
用户请求 → 模型判断需要调用哪个工具 → 生成参数 → 外部执行 → 结果回填给模型
```

### 工具注册

工具需要向模型注册，通常包含：

- 工具名称
- 工具描述
- 参数定义（类型、必填、说明）

工具描述的质量直接影响模型的选择准确率。

### 参数生成

模型根据用户请求和工具描述，生成符合 schema 的参数。

常见问题：

- 参数类型错误
- 必填参数遗漏
- 参数值不合理

### 结果回填

工具执行完成后，结果需要回填给模型，模型再决定下一步行动。

## 工具设计原则

1. **职责单一**：每个工具只做一件事
2. **描述清晰**：工具描述要让模型能准确理解
3. **参数明确**：参数类型和约束要严格定义
4. **结果结构化**：返回值要有固定格式
5. **错误可捕获**：执行失败要返回错误信息

## 面试表达

可以这样表达：

> Tool Calling 是 Agent 系统的核心能力。我的理解是，工具不是简单地"调一下 API"，而是需要设计完整的注册、选择、执行、结果回填和错误处理链路。工具描述的质量直接影响模型的选择准确率，所以我会特别关注工具的命名、描述和参数定义。
