# AI Agent 产品需求文档 PRD 模板

## 这篇文章解决什么问题

技术同学做 Agent 项目时，经常直接写代码，缺少产品需求文档。结果：

- 用户是谁不清楚。
- 功能范围不断膨胀。
- UI 只剩一个聊天框。
- 成功指标不明确。
- 不知道哪些动作要审批。
- 评测和上线标准缺失。

PRD 的目标是把 Agent 产品从“技术能力”翻译成“用户价值、功能范围、交互流程和验收标准”。

## PRD 结构

```text
1. 背景和目标
2. 用户和场景
3. 用户故事
4. 功能范围
5. 非目标
6. 核心流程
7. 页面和交互
8. 权限和审批
9. 数据和指标
10. 评测和验收
11. 风险和开放问题
```

## 背景和目标

写清楚：

- 为什么现在做？
- 当前流程有什么痛点？
- Agent 能带来什么价值？
- 成功后用户行为会怎样变化？

不要写：

```text
我们要做一个 AI Agent。
```

要写：

```text
售后工程师每天需要在多个手册中查找故障处理步骤，平均耗时 10 分钟。目标是通过 RAG Agent 在 1 分钟内给出带引用的处理建议，并支持生成工单草稿。
```

## 用户故事

```text
作为售后工程师，我希望输入故障现象后得到带引用的处理建议，以便快速回复客户。

作为主管，我希望高风险工单发送前需要审批，以便避免错误外发。

作为运营人员，我希望查看失败任务和用户反馈，以便改进知识库和 Prompt。
```

## 功能范围

| 功能 | 说明 | 优先级 |
|---|---|---|
| 文档上传 | 支持 PDF/Word | P0 |
| RAG 问答 | 答案带引用 | P0 |
| 工单草稿 | 结构化生成 | P1 |
| 工具审批 | 高风险动作确认 | P1 |
| 反馈入口 | 点踩和原因 | P0 |
| 运营台 | 失败任务查看 | P2 |

## 非目标

- 不做自动关闭工单。
- 不支持无权限跨部门检索。
- 不保证回答所有问题。
- 不替代人工最终决策。

## 核心流程

```text
上传知识库文档
  -> 入库完成
  -> 用户提问
  -> Agent 检索证据
  -> 生成答案
  -> 用户反馈 / 创建草稿
  -> 必要时人工审批
```

## 页面和交互

不要只有聊天框。考虑：

- 任务状态面板。
- 证据引用面板。
- 工具调用卡片。
- 审批弹窗。
- 反馈入口。
- 历史任务列表。
- 运营台。

## 权限和审批

写清楚：

- 用户角色。
- 可见文档范围。
- 可调用工具。
- 高风险动作。
- 审批人。
- 审计日志。

## 数据和指标

产品指标：

- activation rate。
- task success rate。
- time to answer。
- feedback rate。
- human takeover rate。
- retention。

工程指标：

- p95 latency。
- cost per task。
- citation accuracy。
- schema pass rate。
- tool success rate。
- permission leak rate。

## 验收标准

示例：

- 上传 3 个测试文档后，状态从 processing 变为 ready。
- 用户提问后，答案必须包含至少 1 个引用。
- 无权限用户不能检索 admin 文档。
- 创建工单前必须展示草稿，不直接提交。
- 点踩反馈能在运营台看到。
- 核心 smoke eval 通过率 >= 95%。

## 风险和开放问题

| 风险 | 处理 |
|---|---|
| 检索不准 | 建立 RAG debug 和评测集 |
| 用户不信任 | 展示引用和执行轨迹 |
| 成本过高 | 模型路由和上下文预算 |
| 工具误调用 | 审批和幂等 |
| 数据泄漏 | 权限过滤和审计 |

## 面试表达模板

> 我会为 Agent 产品写 PRD，把技术能力转成用户故事、功能范围、交互流程和验收标准。PRD 会明确目标用户、场景、P0/P1 功能、非目标、任务流程、页面模块、权限审批、产品指标和工程指标。对于 Agent 产品，我不会只设计聊天框，而会设计任务状态、证据引用、工具调用卡片、审批弹窗、反馈和运营台。验收标准同时包含用户流程、权限安全、评测通过率和成本延迟指标。
